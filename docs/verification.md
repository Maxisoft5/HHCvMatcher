# Проверка браузерной реализации

Дата: 29.10.2026. Windows, .NET SDK 10.0.400, Node.js 24.21.0, Microsoft.Playwright 1.64.1.

- `dotnet test`: 73 теста прошли, включая настоящий Chromium на изолированных страницах и React UI.
- Тестовый браузерный сценарий: почта → ожидание кода → неверный код → верный код → подтверждённый профиль → две страницы вакансий. Внешние письма в тестах не отправляются.
- Проверены CAPTCHA как ручной шаг, гостевой заголовок, запрет кода без письма, cooldown, маскирование адреса, отсутствие OTP в состоянии и истечение сессии.
- `npm run build`: TypeScript и production build Vite прошли.
- Установка Chromium через `--install-browser` прошла.
- Живая публичная проверка `--probe-hh` прошла: 20 карточек, 20 с описаниями, 19 с рейтингом, 12 проходят строгий .NET-фильтр; hh.ru сообщил 389 вакансий. Это результат конкретной выдачи на момент проверки, числа меняются.
- Вручную изучена актуальная разметка почтовой формы и выдачи hh.ru через браузер. Используются наблюдавшиеся `data-qa`.
- Живая проверка `--probe-login` прошла: браузер перешёл к пустому полю почты, `emailFormReady=true`. Адрес не вводился, письмо не запрашивалось.
- Добавлены регрессионные проверки задержанной гидратации React и скрытых копий переключателя почты.

TDD: 12 новых проверок сначала падали на заглушках входа и парсера, затем прошли после реализации. Старые API-тесты заменены актуальными проверками браузера и DOM.

**Настоящий вход проверен:** после подтверждённого пользователем запроса письма код введён через UI, сессия перешла в `authenticated`. Синхронизация успешно прочитала 3 страницы / 60 настоящих вакансий, ошибок нет; hh.ru сообщил 403 результата. Почта, код и данные браузерной сессии в этот файл не включены.

На живой выдаче найдены посторонние роли со случайным упоминанием .NET: поддержка, геотехника, AI operations и Unity/Unigine. Добавлены 6 регрессионных случаев (сначала воспроизведено падение), после чего строгий режим усилен: нейтральный заголовок должен соответствовать роли разработки. Кириллические С#/С++ приводятся к тому же стеку, что латинские C#/C++.

После усиления правил из загруженных 60 карточек осталось 15 вакансий разработки. Подтверждено восстановление авторизованной сессии после перезапуска backend без нового письма/кода. При одинаковом соответствии сохраняется порядок выдачи hh.ru; время чтения последней страницы не выдаётся за свежесть публикации.

## Сопроводительные письма

- Сначала добавлены падающие проверки отсутствующей реализации, затем реализованы архив, полный контекст, генерация и версии. Новые тесты проверяют отсутствие обращений к модели/браузеру при чтении, обязательный профиль, реальное полное описание, двойной клик, ошибки без потери писем, редактирование и повторное открытие SQLite после удаления вакансии из текущей выдачи.
- Codex-процесс подменён в unit/HTTP-тестах: проверены вход ChatGPT, отказ от API-key-входа, Sol → Terra только при недоступности, отсутствие повтора при квоте, stdin вместо аргументов и проверка завершённого JSONL-ответа. Настоящая генерация в автотестах не запускается.
- Браузерный UI-тест production React прошёл: открыть окно (0 генераций) → нажать (1) → править → сохранить → открыть повторно (по-прежнему 1). Проверен экран 390px. Провайдер в этом тесте вымышленный, лимиты ChatGPT не расходуются.
- В живом локальном сервере `/api/cover-letters/provider` подтвердил установленный CLI и `Logged in using ChatGPT`. Используется Codex CLI 0.165.0-alpha.1.2. Доступ к Sol/Terra без inference не объявляется подтверждённым.
- В живом React UI окно реальной вакансии открылось, POST генерации — 0. Локальное резюме/навыки пока пусты, кнопка генерации корректно отключена. Настоящее письмо по пользовательскому резюме ещё не генерировалось.
- Отдельный временный Chromium прочитал реальную публичную вакансию: HTTP 200, `[data-qa='vacancy-description']`, 721 символ. Подтверждена актуальность селектора полного текста; страница не требовала входа. Это проверка чтения публичной страницы, а не подтверждение сессии пользователя.
- При последнем перезапуске сохранённая сессия hh.ru не подтвердилась; повторная проверка также вернула disconnected. Предыдущая выдача в базе сохранена. Новые письма с OTP не запрашивались; для чтения через подключённый аккаунт потребуется повторный вход в UI.
