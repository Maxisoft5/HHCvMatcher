# Stack Scout — вакансии C# / .NET через Playwright

Локальное приложение на **.NET 10 / C# 14 + React 19.3 + TypeScript + SQLite**. Вход в hh.ru выполняется через браузер: **почта → запрос письма → ручной ввод кода в UI**. После подтверждения сессии Playwright читает HTML вакансий и передаёт их в список с фильтрами.

**Токен API, регистрация приложения на dev.hh.ru, client_id, client_secret и Redirect URI больше не используются.** Предыдущая интеграция через API удалена. Пароль аккаунта приложению не нужен. Отклики и сообщения работодателям приложение не отправляет.

## Требования

- **.NET SDK 10**, не только Runtime: [загрузка Microsoft](https://dotnet.microsoft.com/download/dotnet/10.0). `global.json` задаёт SDK от 10.0.400 с обновлением внутри .NET 10.
- **Node.js 24 LTS** и npm: [загрузка Node.js](https://nodejs.org/).
- PowerShell 5.1 или 7 на Windows для `start.ps1`.
- Интернет для первой установки NuGet/npm и Chromium. Chromium для Playwright устанавливается автоматически скриптом запуска в кэш проекта; ориентировочно понадобится несколько сотен МБ.
- Действующий аккаунт соискателя hh.ru и доступ к его почте.

Проверка:

```powershell
dotnet --version
node --version
npm --version
```

Docker, SQL Server, API-ключи и расширения браузера не нужны. Используется отдельный Chromium, обычный профиль Chrome/Edge пользователя приложение не открывает.

## Запуск одной командой

В PowerShell перейдите в папку проекта:

```powershell
.\start.ps1
```

Скрипт:

1. Восстанавливает пакеты .NET.
2. Устанавливает frontend по `package-lock.json` и собирает React.
3. Копирует UI в `src/HhScout.Api/wwwroot`.
4. Собирает .NET в Release.
5. Проверяет и при необходимости устанавливает Chromium для текущей версии Playwright.
6. Запускает один локальный сервер.

Откройте **[http://127.0.0.1:5077/](http://127.0.0.1:5077/)**. Терминал оставьте открытым. Остановка — **Ctrl+C**.

Повторный запуск готовой сборки:

```powershell
.\start.ps1 -NoBuild
```

После изменения исходников запускайте без `-NoBuild`. Перед полной сборкой остановите ранее запущенный backend и Vite: Windows может удерживать `.exe` и native-модули npm открытыми.

Для просмотра интерфейса без аккаунта и запросов к hh.ru:

```powershell
.\start.ps1 -Demo
```

Демо явно подписано; вакансии и компании вымышлены. База демо отделена от настоящей базы. В режиме `-Demo` почтовый вход отключён, Chromium не требуется.

Если PowerShell запрещает локальные `.ps1`, используйте ручной запуск из раздела ниже или разрешённую вашей системой политику выполнения локальных скриптов. Администратор для обычного запуска не нужен.

## Вход по почте и коду

1. В блоке **«Войдите в hh.ru по почте»** укажите почту существующего аккаунта.
2. Нажмите **«Получить код»**. Backend откроет отдельный Chromium, выберет почтовый вход на hh.ru и отправит форму.
3. Дождитесь письма. Поле кода появляется после обнаружения соответствующего шага на hh.ru; приложение не утверждает, что письмо отправлено, только по факту клика.
4. Введите код вручную в локальном UI и нажмите **«Подтвердить вход»**.
5. При обнаружении признаков авторизованного аккаунта появится **«hh.ru подключён»**. Начнётся загрузка вакансий.
6. Введите запрос, выберите регион и используйте кнопку **«Найти вакансии»**. Далее обновление выполняется каждые 5 минут, пока работает backend.

Код не сохраняется в SQLite и не записывается в логи приложения. После отправки поле в UI очищается. В статусе backend возвращает только маскированную почту. Запрос нового письма ограничен паузой в одну минуту; проверка неверного кода сама по себе новое письмо не отправляет.

**Если hh.ru просит CAPTCHA, дополнительное подтверждение или показывает неожиданную форму:**

1. Нажмите **«Открыть браузер hh.ru»**.
2. Выполните требуемое действие вручную в открытом Chromium.
3. Вернитесь в UI и нажмите **«Проверить вход»**.

Приложение не решает CAPTCHA и не обходит ограничения сайта. Регистрация нового аккаунта автоматически не выполняется: если hh.ru предлагает регистрацию, нужно проверить почту и продолжить самостоятельно.

Сессия сохраняется в отдельном локальном браузерном профиле. После перезапуска backend пытается восстановить её при первой синхронизации. Кнопка **«Проверить сохранённый вход»** позволяет проверить её вручную. Сохранённый профиль сам по себе не считается доказательством авторизации — проверяются элементы страницы.

Кнопка **«Отключить и забыть вход»** закрывает управляемый браузер и удаляет его отдельный локальный профиль. Она не отключает остальные устройства в аккаунте hh.ru. Ваш профиль навыков и снимок вакансий остаются в SQLite.

Не запускайте два экземпляра приложения с одним браузерным профилем.

## Точный подбор под C# и .NET

Строгий режим включён по умолчанию. Сначала определяется основной стек вакансии, затем применяются обязательные навыки и рассчитывается соответствие вашему профилю.

| Заголовок / требования | Строгий режим |
| --- | --- |
| `Senior C# / .NET Developer` | Допускается |
| `Fullstack .NET / React` | Допускается |
| `Java Developer`, в тексте упомянут .NET | Исключается |
| `Frontend React Developer (.NET backend)` | Исключается |
| `QA .NET engineer`, `SDET C#`, `Системный аналитик .NET` | Исключается |
| Поддержка, геотехника, AI operations или Unity/Unigine с упоминанием .NET | Исключается |
| `Backend Developer`, в snippet есть C# и .NET | Допускается |
| Нейтральный заголовок, в snippet только одно упоминание .NET | Исключается без явных тегов навыков |

Названия с другим основным языком, включая смешанные `Java / C#`, исключаются намеренно. Отдельный frontend не проходит, если нет признака fullstack или Blazor. Нейтральный заголовок требует обоих признаков C# и .NET в тексте либо явного подходящего тега навыков.

Кроме технологий, нейтральный заголовок должен обозначать разработку: developer, программист, backend/fullstack, архитектор или технический лидер. Наличие C#/.NET в описании специалиста поддержки не превращает его в вакансию разработчика. Поддерживаются и кириллические варианты `С#`/`С++` в заголовках.

Рекомендуемая настройка:

1. Оставьте **«Только C# и .NET»** включённым.
2. Через **«Мои навыки»** добавьте свой стек, например `C#, .NET, ASP.NET Core, PostgreSQL, Docker, Redis`.
3. В **«Обязательные навыки»** укажите только навыки, которые должны быть в вакансии. Здесь правило **AND**: нужен каждый. Например, `ASP.NET, PostgreSQL`.
4. При необходимости добавьте порог соответствия, зарплату, валюту, удалёнку и название компании.
5. Откройте **«Разобрать совпадение»**, чтобы увидеть подтверждающие навыки и отсутствующие требования.

Процент = число совпавших навыков / число обнаруженных навыков вакансии × 100. Нет профиля или нет требований — выводится «Без оценки», а не выдуманный процент.

Распознаются синонимы: `c sharp → C#`, `dotnet → .NET`, `ASP.NET Core → ASP.NET`, `React.js → React`, `SQL Server → MS SQL`. Java не совпадает с JavaScript. PostgreSQL не приравнивается к MS SQL. Автоматическое выделение навыков из текста ограничено словарём; редкие технологии можно указать вручную в профиле.

Это предварительное сравнение найденных технологий. Уровень seniority, домен, годы опыта и версии .NET пока не являются отдельными правилами оценки. Краткий текст может быть неполным: строгий фильтр предпочитает скрыть сомнительную вакансию. Полные требования проверяйте по ссылке на hh.ru.

## Что именно читается с hh.ru

Playwright открывает `/search/vacancy`, запрашивает расширенное описание (`enable_snippets=true`) и читает видимый HTML. Скрытые внутренние API сайта не вызываются.

Из карточек извлекаются:

- ID, заголовок, работодатель и ссылка.
- Регион, опыт и признак удалённой работы.
- Зарплата: нижняя/верхняя границы, валюта, налоги и период выплаты, если он указан.
- Краткие требования и обязанности, технологии по словарю либо явным тегам.
- Рейтинг работодателя и количество отзывов, если они показаны на странице.
- Дата публикации только при наличии машинно читаемой даты в HTML. Иначе показывается **«Проверено …»**, а не выдуманная дата публикации.

**Тексты отзывов, резюме из аккаунта, отклики, сообщения и чаты не собираются.** Вставленный вами текст резюме нужен только для локального сопоставления навыков.

Рейтинг страницы помечается как рейтинг hh.ru. Размер компании обычно неизвестен; его можно добавить вручную вместе со своей оценкой и источником. Ручные сведения имеют приоритет над автоматическими данными этой компании.

Фильтр **«Зарплата в месяц»** сравнивает только суммы, явно помеченные как месячные, и только в выбранной валюте. Почасовые, посменные и суммы без известного периода не смешиваются с месячными. Налоги и курсы валют не пересчитываются. Диапазон 200–300 тыс. проходит порог 250 тыс.; «от 200 тыс.» также проходит, поскольку верхняя граница не ограничена. Неизвестная зарплата при заданном пороге исключается.

## Сопроводительные письма через Codex / ChatGPT

**Модель вызывается только кнопкой «Сгенерировать письмо» или «Создать новую версию».** Открытие карточки/окна письма, запуск backend, проверка входа Codex и обновления вакансий не вызывают модель. Письма не отправляются работодателям.

### Подготовка Codex

Нужен установленный **Codex CLI** с поддержкой `codex exec --ignore-user-config --ephemeral --output-schema`. На машине разработки проверен `codex-cli 0.165.0-alpha.1.2`. Можно использовать CLI из установленного приложения Codex Desktop. Backend ищет `codex.exe` в PATH, затем в `%LOCALAPPDATA%/OpenAI/Codex/bin`; на других ОС ищет `codex` в PATH. Для нестандартного расположения задайте полный путь к исполняемому файлу:

```powershell
$env:Codex__Executable = 'C:\путь\к\codex.exe'
& $env:Codex__Executable --version
& $env:Codex__Executable login
& $env:Codex__Executable login status
.\start.ps1
```

При `codex login` выберите вход через **ChatGPT** в браузере. Если `codex` уже есть в PATH, достаточно `codex login` и `codex login status`. Ожидаемый статус — `Logged in using ChatGPT`. Запускайте backend под тем же пользователем ОС. Если CLI уже авторизован приложением Codex, повторный вход обычно не нужен. Сама открытая вкладка chatgpt.com без авторизованного CLI недостаточна.

API-ключ OpenAI не нужен. Приложение повторно использует штатную авторизацию CLI; не извлекает токены из браузера или файлов авторизации и не копирует их в SQLite. `OPENAI_*` и `CODEX_API_KEY` удаляются из окружения дочернего процесса, вход с API-ключом отклоняется. Для другого каталога штатных настроек/авторизации можно задать `$env:Codex__Home='C:\путь\.codex'`. Подписка и её лимиты должны разрешать выбранную модель.

### Работа в UI

1. Откройте **«Мой профиль»**, сохраните навыки и желательно текст резюме. Именно локальный профиль передаётся модели; резюме из аккаунта hh.ru автоматически не скачивается.
2. В карточке вакансии нажмите **«Сопроводительное»**. Окно показывает ранее сохранённые версии, наличие описания и состояние входа CLI. На этом шаге генерации нет.
3. Выберите **Автоматически**, **GPT-6.1 Sol** или **GPT-6.1 Terra**. По умолчанию используется Sol; переход на Terra возможен только при явной ошибке недоступности Sol. Ошибки входа, лимитов и сети не запускают вторую попытку. Наличие CLI/входа ещё не гарантирует доступ к модели: это станет известно при настоящем запросе.
4. Нажмите **«Сгенерировать письмо»**. Если полного описания ещё нет, Playwright откроет страницу выбранной вакансии в подключённой сессии, прочитает блок `vacancy-description` и сохранит его. Затем CLI получит описание, название, компанию, ссылку и локальное резюме/навыки. Обычно ожидание занимает до нескольких минут; по умолчанию таймаут модели — 180 секунд. Параллельная генерация отклоняется.
5. Проверьте результат, при необходимости отредактируйте и нажмите **«Сохранить правки»**. **«Копировать»** копирует текущий текст. Новая генерация создаёт отдельную версию; старые остаются в списке. Повторное открытие показывает сохранённый черновик без вызова модели.

Блок **«Контекст вакансии»** позволяет посмотреть полный текст, дату получения и отдельно сохранить/обновить описание без генерации. По умолчанию повторная генерация использует сохранённое описание; актуализировать его можно этой кнопкой. При изменении резюме или описания старое письмо получает предупреждение об изменении контекста. Ошибка hh.ru или Codex не удаляет готовые версии. После изменения модели для существующего письма нажмите «Создать новую версию».

Полные описания загружаются для выбранных вакансий по действию пользователя, а не для всей выдачи каждые 5 минут. Поэтому обычный поиск остаётся лёгким и не расходует лимиты модели. В SQLite сохраняются полный текст до 200 000 символов, дата и SHA-256; модели передаются первые 60 000 символов описания и до 30 000 символов резюме. При большом описании UI сообщает об ограничении. Ранжирование списка пока использует snippets и навыки карточек, загрузка полного текста сама по себе не меняет формулу ранжирования.

Каждая версия хранит исходный и редактируемый текст, фактически использованную модель, даты и снимок резюме/описания. **База содержит персональные данные, включая предыдущие версии резюме, использованные для писем.** Сброс текущего профиля не удаляет эти снимки. Архив и письма хранятся локально без автоматического срока удаления; для полного сброса сделайте резервную копию и удалите локальную базу при остановленном backend.

Codex запускается отдельным процессом без shell, с запросом через stdin, read-only sandbox, запретом запросов разрешений, отключёнными интеграциями и инструментами. Пользовательский `config.toml` при генерации не загружается, сессия CLI не сохраняется (`--ephemeral`). В логи приложения не попадают prompt, ответ модели и сырые ошибки CLI. Указания внутри вакансии трактуются как данные; письмо должно опираться только на факты из вашего профиля. Всё равно проверяйте факты перед использованием.

Официальные справки: [неинтерактивный запуск Codex](https://learn.chatgpt.com/docs/non-interactive-mode), [вход через ChatGPT](https://learn.chatgpt.com/docs/auth).

## Обновление и сохранение данных

Карточки дополнительно сохраняются в архиве SQLite по ID. Архив, полные описания и версии сопроводительных писем не удаляются при замене текущего списка поиска.

- Первый запуск синхронизации — при старте backend. Если вход ещё не выполнен, запрос вакансий не запускается.
- После успешного входа через UI выполняется загрузка. Затем проверка — каждые 5 минут после завершения предыдущей попытки.
- Ручное обновление переносит следующую автоматическую попытку на 5 минут.
- По умолчанию читаются до **3 страниц**. Число карточек на странице определяет hh.ru; параметр `items_on_page=50` не гарантирует, что сайт отдаст ровно 50. При живой проверке одна страница содержала 20 карточек.
- Между страницами пауза 1 секунда. Запросы одного браузерного профиля выполняются последовательно.
- Это ограниченный снимок последней выдачи, а не обход всей базы hh.ru. Уточняйте запрос, если нужные вакансии остаются за лимитом.
- Снимок и его метаданные заменяются одной транзакцией SQLite после успешной загрузки всех настроенных страниц.
- При ошибке, истёкшей сессии или изменении разметки предыдущий снимок остаётся доступен.
- Если сменился запрос, а загрузка не удалась, UI помечает старый снимок как результат предыдущего поиска.
- UI проверяет локальный backend каждые 10 секунд. Это не дополнительные обращения к hh.ru.

При остановленном backend, спящем компьютере или выключенном интернете автоматической загрузки нет. Закрытая вкладка UI не останавливает работающий backend.

## Запуск для разработки

### Терминал 1 — .NET

Из корня проекта:

```powershell
dotnet restore --configfile .\NuGet.Config
dotnet build --no-restore
dotnet run --no-build --no-launch-profile --project .\src\HhScout.Api -- --install-browser
dotnet run --no-build --no-launch-profile --project .\src\HhScout.Api
```

API: **http://127.0.0.1:5077**. Проверка: [http://127.0.0.1:5077/api/health](http://127.0.0.1:5077/api/health) → `{"status":"ok"}`.

`--install-browser` только устанавливает/проверяет Chromium и завершает процесс. Сервер при этой команде не запускается. Кэш по умолчанию — `src/HhScout.Api/.cache/playwright`.

### Проверка живой разметки без входа

Для диагностики парсера предусмотрена одна публичная страница в отдельном временном контексте Chromium:

```powershell
dotnet run --no-launch-profile --project .\src\HhScout.Api -- --probe-hh
```

Команда выводит JSON с количеством карточек, описаний, рейтингов и .NET-совпадений. Она не отправляет почту, не использует сохранённую сессию и не является проверкой входа в аккаунт. Если hh.ru запросит проверку или откажет в доступе, диагностическая команда завершится с ошибкой, ничего не обходя.

Отдельно можно проверить только переход к пустому полю почты, без ввода адреса и без запроса письма:

```powershell
dotnet run --no-launch-profile --project .\src\HhScout.Api -- --probe-login
```

Успешный результат содержит `emailFormReady: true`. Используется новый временный контекст, а не ваш сохранённый профиль. Диагностика проверяет тот же переход, что и продуктовый вход.

## Тесты

Остановите backend соответствующей конфигурации перед пересборкой тестов. Первый раз установите Chromium:

```powershell
dotnet restore --configfile .\NuGet.Config
dotnet build --no-restore
dotnet run --no-build --no-launch-profile --project .\src\HhScout.Api -- --install-browser
Push-Location .\web
npm ci
npm run build
Pop-Location
dotnet test --no-restore
```

Быстрый запуск без браузерных тестов:

```powershell
dotnet test --no-restore --filter 'Category!=Browser&Category!=UI'
```

Проверка production frontend:

```powershell
Push-Location .\web
npm ci
npm run build
Pop-Location
```

Тесты не используют настоящий аккаунт и не отправляют письма. Проверяются:

- Почта → код → подтверждённая сессия; запрет кода без предыдущего запроса.
- Валидация почты, ограничение повторных писем, неверный код, CAPTCHA и истечение сессии.
- Отсутствие кода и полного адреса почты в статусе сессии.
- Настоящий Chromium на изолированных HTML-страницах: почтовая форма, неверный/верный код, две страницы выдачи, гостевой профиль и CAPTCHA.
- HTML-парсер текущих `data-qa`, карточки с несколькими токенами `data-qa`, рекламные ссылки с ID карточки, snippets, рейтинг и пагинация.
- Зарплаты, валюты, налоги, периоды выплат, отсутствие выдуманной даты публикации.
- Строгий C#/.NET, алиасы, обязательные навыки, проценты, сортировка и неизвестные данные.
- HTTP API, валидация, чужой Origin, SQLite, дедупликация, сохранность снимка при сбое и запрет параллельных синхронизаций.
- Генерация только по явному запросу, отсутствие вызовов модели при чтении контекста, полный контекст, версии/редактирование, повторное открытие SQLite и защита от двойного клика.
- Автовыбор Sol → Terra только при недоступности модели, отсутствие повтора при лимитах, отказ от API-key-входа, prompt через stdin и проверка JSONL-ответа CLI.
- Настоящий React UI в Chromium: открыть без генерации → нажать кнопку → править → сохранить → открыть повторно; узкий экран. Модель в тесте подменена, лимиты ChatGPT не используются.

TDD: новые тесты сначала воспроизвели отсутствие реализации входа, HTML-парсера и сопроводительных писем, затем были реализованы соответствующие классы. Тесты браузерного драйвера помечены `Category=Browser`, тест React — `Category=UI`. Перед UI-тестом нужна production-сборка `web/dist`; в CI она и Chromium готовятся перед тестами. Для Linux предусмотрен `--install-browser --with-deps`.

Результаты текущих проверок и границы проверки настоящего входа — [docs/verification.md](docs/verification.md).

## Настройки

Основные параметры — `src/HhScout.Api/appsettings.json`. Переменные окружения имеют приоритет; вложенные ключи разделяются двойным подчёркиванием. `.env` автоматически не читается.

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `Hh__MaxPages` | `3` | Максимум страниц за попытку; ограничивается диапазоном 1–10 |
| `Hh__PollingEnabled` | `true` | Автопроверка каждые 5 минут; `false` оставляет ручное обновление |
| `Hh__Demo` | `false` | Явный режим вымышленных примеров |
| `Browser__Headless` | `false` | Обычное видимое окно Chromium для ручных проверок |
| `Browser__Diagnostics` | `false` | Включает локальный диагностический endpoint с именами полей/кнопок и этапом перехода; значения полей и cookies не возвращаются |
| `Storage__Path` | `data/scout.db` | Путь SQLite относительно каталога backend |
| `PLAYWRIGHT_BROWSERS_PATH` | `src/HhScout.Api/.cache/playwright` | Необязательное переопределение пути браузерных бинарников; установка и запуск должны использовать одинаковое значение |
| `Urls` | `http://127.0.0.1:5077` | Адрес локального сервера |
| `Codex__Executable` | Автопоиск | Полный путь к нативному `codex.exe` / `codex`, не `.ps1` / `.cmd` |
| `Codex__Home` | `CODEX_HOME` или `~/.codex` | Каталог штатной авторизации Codex; не копируйте токены в проект |
| `Codex__TimeoutSeconds` | `180` | Таймаут генерации от 30 до 600 секунд, включая возможный переход на Terra |

По умолчанию окно Chromium видно и его можно свернуть. Скрытый режим задаётся `$env:Browser__Headless='true'`, но ручная CAPTCHA в нём недоступна: потребуется перезапуск с `false` и проверка сохранённого входа. Для первого входа рекомендуется стандартный видимый режим.

Старые `Hh__ApplicationToken` и `Hh__UserAgent` не используются и могут быть удалены из вашего окружения.

## Хранение сессии и резервные копии

```text
src/HhScout.Api/data/scout.db          # профиль, компании, снимок/архив, описания, версии писем и их контекст
src/HhScout.Api/data/scout.demo.db     # отдельные демонстрационные данные
src/HhScout.Api/data/hh-browser/       # отдельный профиль Chromium с сессией hh.ru
src/HhScout.Api/data/codex-letters/    # рабочая папка CLI и публичная JSON-схема ответа
src/HhScout.Api/.cache/playwright/     # загруженные браузерные бинарники
```

`data`, `.cache`, зависимости и сборки исключены из Git. **Браузерный профиль содержит данные сессии: не отправляйте его другим людям и не добавляйте в репозиторий.** Код из письма отдельно в базу не записывается; полная почта в статусе backend не возвращается.

Для резервной копии SQLite остановите backend и скопируйте `scout.db` вместе с `scout.db-wal`/`scout.db-shm`, если они остались. Включать браузерный профиль в резервную копию необязательно — можно войти повторно.

Для сброса только входа используйте кнопку «Отключить и забыть вход». Для сброса всей локальной базы остановите backend и переместите нужные `.db` и их WAL/SHM-файлы в резервную папку. Это сбросит и локальный профиль навыков.

Приложение рассчитано на одного пользователя и localhost. Не публикуйте порт в интернет: серверной многопользовательской аутентификации здесь нет.

## Ошибки и решения

| Симптом | Что делать |
| --- | --- |
| «Codex CLI не найден» | Установите CLI или задайте `Codex__Executable` с полным путём к нативному файлу, затем перезапустите backend |
| Кнопка генерации недоступна | Сохраните профиль/навыки; проверьте `codex login status`: нужен вход через ChatGPT, а не API-ключ |
| CLI не понимает `--ignore-user-config` / `--ephemeral` | Обновите Codex CLI. Смотрите `codex exec --help`; флаги относятся к подкоманде `exec` |
| Sol / Terra недоступна | Выберите другую модель или автоматический режим; перечень в UI не является гарантией доступа по подписке |
| Ошибка лимитов/сети или таймаут Codex | Проверьте CLI и лимиты ChatGPT. Автоповтора нет; сохранённые версии не изменяются. Повтор запускается вашей кнопкой |
| Полное описание не прочитано | Проверьте вход hh.ru, наличие вакансии и разметку `[data-qa='vacancy-description']`; краткий snippet не подставляется вместо полного текста |
| «Подключите hh.ru» | Введите почту и код либо проверьте сохранённый вход |
| Письмо не пришло | Проверьте спам и правильность почты; посмотрите окно Chromium. Через минуту можно запросить новый код |
| «hh.ru не принял данные» | Проверьте код/почту в браузере, при необходимости запросите новый код; приложение не раскрывает исходный текст формы с персональными данными в статусе |
| CAPTCHA / ручная проверка | «Открыть браузер hh.ru» → пройти проверку самостоятельно → «Проверить вход» |
| Форма не перешла к ожидаемому шагу | Посмотрите окно Chromium. Возможно, hh.ru изменил разметку или требуется дополнительное действие |
| Вместо входа предлагается регистрация | Проверьте, что почта принадлежит существующему аккаунту. Автоматическая регистрация отключена |
| Сессия истекла | Войдите повторно; старый снимок сохранён |
| «Не удалось запустить Chromium» | Выполните команду `--install-browser`; закройте второй экземпляр приложения с тем же профилем |
| Браузер не открывается по кнопке | При `Browser__Headless=true` нужен перезапуск с `false` |
| `403`, `429` или ограничение hh.ru | Не нажимайте обновление многократно; проверьте браузер, дождитесь следующей попытки. Проверки сайта не обходятся |
| «Не удалось распознать карточки» | Предыдущие данные сохранены. Проверьте `--probe-hh` и селекторы в `HhHtmlParser.cs`; сайт мог изменить HTML |
| Ничего не найдено после фильтров | Уберите слишком узкий обязательный навык: он мог отсутствовать в snippet. При AND нужен каждый навык |
| Не видна месячная зарплата | Сумма могла быть почасовой, посменной, в другой валюте или без известного периода |
| Нет размера компании / рейтинга | Данные могут отсутствовать на hh.ru; размер можно добавить вручную в раскрытой карточке |
| UI пишет, что backend недоступен | Проверьте сервер на 5077 и `/api/health`; Vite на 5173 требует отдельного backend |
| Порт занят | Остановите ранее запущенный экземпляр через Ctrl+C |
| Backend запущен, главная страница 404 | Соберите через `start.ps1` без `-NoBuild`; при разработке открывайте Vite на 5173 |
| `NU1301`, ошибка npm / загрузки Chromium | Проверьте доступ к NuGet, npm и `cdn.playwright.dev`, proxy и ограничения среды. Проверку TLS отключать не нужно |
| Блокировка `.exe` / native-модуля npm | Перед пересборкой остановите соответствующий backend и Vite |
| После изменения кода ничего не поменялось | Перезапустите без `-NoBuild` или используйте Vite в режиме разработки |
